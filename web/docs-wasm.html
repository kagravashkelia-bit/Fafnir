WebAssembly

Fafnir WebAssembly status, Emscripten build, the five-function C API, JavaScript usage, CI artifact and current limitations.

Fafnir 2.0Updated 2 November 2026Reference
!
Status: in preparationThe public WebAssembly edition is in preparation. CI builds an artifact named Fafnir-WASM-Build on every push, and the C API below is implemented, but there is no supported browser release yet. Treat this page as an API reference for review and testing.

Building

The WASM build uses Emscripten and a separate makefile. It does not require the native toolchain.

Emscripten buildbash
# requires emcc in PATH
make -f Makefile.wasm

# output
build-wasm/Fafnir.js
build-wasm/Fafnir.wasm

Network embedding is disabled for WASM with NNUE_EMBEDDING_OFF. The artifact therefore does not contain the 94 MB network inside the wasm binary. The public edition will need a deliberate strategy for the network (separate download, reduced artifact, or a server-side search) that is not finalized yet.

C API

The header src/ui/fafnir_wasm_api.h declares five functions. They are compiled only under __EMSCRIPTEN__ and exported with EMSCRIPTEN_KEEPALIVE.

fafnir_wasm_api.hc
#ifdef __EMSCRIPTEN__
#ifdef __cplusplus
extern "C" {
#endif

int fafnir_init(void);
int fafnir_set_fen(const char* fen);
const char* fafnir_go_movetime(int milliseconds);
void fafnir_stop(void);
int fafnir_eval(void);

#ifdef __cplusplus
}
#endif
#endif
FunctionReturnsBehaviour
fafnir_init1 on success, 0 on errorInitializes the NNUE probe once; repeated calls are safe
fafnir_set_fen1 on success, 0 on errorStops any search, sets the board from a FEN, resets history
fafnir_go_movetimeUCI move string, or 0000Synchronous search for at least 1 ms; returns the best move
fafnir_stopvoidRequests the current search to stop
fafnir_evalinteger, 0 on errorReturns the evaluation of the current board

Calling from JavaScript

With the default Emscripten module, the functions are available through ccall or the exported function table. Strings returned by fafnir_go_movetime are pointers into the WASM heap; copy them with UTF8ToString before the next call.

Browser usagejavascript
const Fafnir = await createFafnirModule();

// initialize once
if (!Fafnir.ccall('fafnir_init', 'number', [], [])) {
  throw new Error('Fafnir failed to initialize');
}

// set a position
const fen = 'rnbqkbnr/pppppppp/8/8/8/8/PPPPPPPP/RNBQKBNR w KQkq - 0 1';
const ok = Fafnir.ccall('fafnir_set_fen', 'number', ['string'], [fen]);
if (!ok) throw new Error('Invalid FEN');

// search synchronously
const ptr = Fafnir.ccall('fafnir_go_movetime', 'string', ['number'], [1000]);
const bestmove = Fafnir.UTF8ToString(ptr);

console.log(bestmove); // e2e4

// raw evaluation
const score = Fafnir.ccall('fafnir_eval', 'number', [], []);
console.log(score);
i
Blocking callThe search call is synchronous. A long movetime blocks the JavaScript thread. The public web edition will need a worker or a cooperative yield loop; do not ship a long synchronous search on the main thread.

CI artifact

The build-wasm.yml workflow runs on every push to main/master. It builds the WASM target and uploads the result as the Fafnir-WASM-Build artifact. The workflow previously failed because its file selection pulled in the JNI bridge and the legacy probe; both are now excluded or removed, and CI no longer mutates the vendored incbin.h.

WorkflowTriggerOutput
build-wasm.ymlPush / PR to main or masterFafnir-WASM-Build artifact
build-native.ymlPush / PR touching engine, assets or MakefileNative archives + UCI smoke test
deploy-pages.ymlChanges under web/This website on GitHub Pages

Current limitations

  • No published browser build or hosted UI.
  • No threading: the C API drives one synchronous search at a time.
  • No network embedding in the WASM artifact.
  • No UCI console in the browser; the C API is the only interface.
  • The API returns a move string, not a full analysis object; a UI needs a separate info channel for depth, score and PV.

What ships next

The roadmap lists the public WASM edition as in preparation, without a date. The API is documented first so it can be reviewed and tested before a UI is built on top of it. See the roadmap for the current state.
