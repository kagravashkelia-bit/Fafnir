Contribute

Contributing

Bug reports, test positions, documentation fixes and focused patches are all welcome. The project is small, so the best contributions are specific, reproducible and easy to review.

Open an issueRead the code
Before you start

Four useful ways to help.

◎

Reproduce a bug

A minimal command, FEN or GUI action plus the raw output is worth more than a description.

✓

Add a test

A legal EPD position with a clear best move strengthens the regression net.

⌘

Fix a narrow issue

One behaviour per pull request. Avoid unrelated reformatting.

¶

Improve the docs

If a page is wrong about the binary, that is a bug in the docs.

Development setup

Build and smoke testbash
git clone https://github.com/kagravashkelia-bit/Fafnir.git
cd Fafnir
make ARCH=native -j8
printf 'uci\nisready\nquit\n' | ./bin/Fafnir

On Windows, use MSYS2 with g++ and make. The default make target builds a safe x86-64 binary; ARCH=native is faster for local work but must not be published as a portable archive.

Run the tests

EPD regressionbash
python tests/tests.py bin/Fafnir.exe --depth 18
python tests/tests.py bin/Fafnir --depth 18 --hash 64 --threads 1

Record the score before and after a search or evaluation change. A drop in one position may be noise; a drop across a category is a regression. See Testing for the suite structure and limitations.

Code guidelines

  • C++17. Match the surrounding style; do not introduce a parallel convention.
  • One concern per patch. A search change and a formatting sweep in the same PR are hard to review.
  • No unrelated reformatting. It obscures the diff and makes bisecting harder.
  • Keep the protocol honest. Do not declare a UCI option before it is implemented and tested.
  • Preserve portability. The Makefile must work in cmd.exe, MSYS2 sh, Linux and macOS shells.
  • Do not mutate vendored code unless the patch is documented in third_party/VENDORED.md.

Changes to search or evaluation

Search and evaluation changes need evidence, not just a plausible argument. Include:

  • The exact change and the reasoning.
  • EPD results before and after, with the same depth, Hash and Threads.
  • Any speed impact, measured with the documented UCI sequence.
  • A note on whether the change affects reproducibility or the network.
i
Report the misses tooA patch that gains one EPD position and loses three is not obviously an improvement. Report the whole result, including the losses.

Commit messages

The project uses descriptive one-line messages rather than semantic presets. A good message says what changed and, when it is not obvious, why:

Examplestext
Search: verify null-move cutoffs at shallow depth
UCI: answer unknown options with an info string
Build: make mkdir idempotent on cmd.exe
Docs: correct the Hash range in the UCI table

Pull request checklist

  • The tree builds with make ARCH=native -j8.
  • The UCI smoke test prints id name Fafnir 2, uciok and readyok.
  • Search/eval changes include EPD results before and after.
  • The change does not add an unimplemented UCI option.
  • Documentation is updated in the same PR when behaviour changes.
  • No generated binaries, build directories or local editor files are committed.

Bug reports

Include the operating system, CPU model, archive or commit, the exact command or GUI action, and the raw engine output. For an illegal instruction, state which ISA build you used. For a protocol issue, paste the complete handshake rather than a single line.

Security

Do not open a public issue for a vulnerability that could affect users. Follow the process in SECURITY.md in the repository. The engine is local and does not open network connections, but build and download integrity still matter.

Code of conduct

Be direct about code and considerate about people. Harassment, personal attacks and deliberate disruption are not welcome. The repository includes CODE_OF_CONDUCT.md; read it before a contentious discussion.

Have a reproducible issue?

Open it with the command, the position and the output. That is the fastest path to a fix.
