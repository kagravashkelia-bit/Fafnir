Troubleshooting

Fix Fafnir startup, illegal-instruction, GUI handshake, unknown option, NNUE, WASM and performance problems with diagnostic commands.

Fafnir 2.0Updated 2 November 2026Reference

Most failures fall into four groups: the binary does not match the CPU, the GUI never completes the UCI handshake, the WASM toolchain is missing, or a search is slower than expected. Start with the symptom table, then use the diagnostic commands at the end.

Quick triage

SymptomMost likely causeFirst action
Process exits immediately on WindowsAVX2/SSE4.2 build on an older CPUUse the safe x86-64 archive
Illegal instruction on LinuxISA mismatchRebuild or download a lower ISA build
GUI shows engine as unavailableHandshake not completedRun the binary manually and send uci
No analysis appearsWrong engine path or protocolVerify id name Fafnir 2 in the GUI log
unknown UCI optionTypo or unsupported optionCompare with the five declared options
emcc: not foundEmscripten not in PATHActivate emsdk and retry
Lower NPS than expectedPower profile, ISA, or Hash/ThreadsCompare with the benchmark protocol

Illegal instruction

This is not a corrupt download. A binary compiled for AVX2 uses instructions that a CPU without AVX2 cannot execute. The safe x86-64 archive runs on any x86-64 CPU. On Linux, confirm the flags:

Check CPU flagsbash
lscpu | grep -o -E 'sse2|ssse3|sse4_2|avx2|avx512f' | sort -u

If avx2 is absent, do not use an AVX2 build. If sse4_2 is absent, use the safe build. On Windows, the processor model in System Information is enough to choose between the three published archives.

Linux: permission or not found

Run the binarybash
chmod +x Fafnir
./Fafnir
# if the shell cannot find it:
./Fafnir-x86-64-avx2

Extracting a tarball does not always preserve the executable bit. The archive may contain a version-suffixed binary; list the directory after extraction.

The GUI does not see the engine

  1. Run the binary in a terminal and send uci. If there is no uciok, the problem is the binary, not the GUI.
  2. Check that the GUI is configured for UCI, not WinBoard/CECP.
  3. Point the GUI at the extracted binary, not the archive or a source file.
  4. On Windows, avoid a path with unusual permissions or a network drive for the first test.
  5. Look at the GUI's engine log; it usually shows the raw handshake and the exact failure.
i
Startup bannerFafnir prints a banner (Fafnir 2) when it starts, before the UCI handshake. A GUI that expects absolute silence until uci may log it as noise; it is not an error.

Unknown option messages

Fafnir declares five options: Hash, Threads, MultiPV, Move Overhead and Aggressivity. If the GUI tries to set anything else — a tablebase path, a book, a Syzygy option — the engine answers:

Responsetext
info string unknown UCI option

Remove the unsupported setting from the GUI profile, or accept the message. It does not stop the search. Do not add options to the GUI profile in the hope that they will work.

The engine cannot find a network

It does not look for one. The native build embeds the SFNNv17 network with incbin. If a guide tells you to download a .nnue file for the published archives, that guide is for a different build. The WASM build is the exception: it disables embedding with NNUE_EMBEDDING_OFF.

WASM build failures

ErrorCauseFix
emcc: command not foundEmscripten not activatedSource emsdk_env.sh or emsdk_env.bat
JNI or jni.h errorsOld workflow file selectionUse the current Makefile.wasm; the JNI bridge is removed
Legacy probe compile errorsOld source listDo not add third_party/stockfish/probe to the build
incbin.h modified locallyAn old CI step mutated itRestore the vendored file and rebuild
Out of memoryEmscripten and a large networkEmbedding is already off; limit parallel jobs

CI failures

JobSymptomLikely fix

build-native.ymlUCI smoke test failsRun the same sequence locally and compare the identity
build-wasm.ymlJNI / probe errorsThe workflow must exclude the removed bridge and legacy probe

Lower performance than expected

  • Safe build. x86-64 is SSE2 only. An AVX2 build is roughly twice as fast on this project's benchmark.
  • Power profile. A laptop on battery or a balanced profile can lose a large fraction of NPS.
  • Threads. More threads do not scale linearly and can reduce NPS per thread. Compare with one thread first.
  • Hash. A tiny hash causes re-search; a huge hash can hurt cache locality. Start at 16–128 MB.
  • Background load. Browsers, antivirus and other engines distort a benchmark.

Diagnostic commands

Collect evidencebash
# identity, options, readiness, one short search
printf 'uci\nisready\nposition startpos\ngo depth 10\nquit\n' | ./bin/Fafnir

# verify the embedded network file in the source tree
sha256sum assets/nnue/nn-252f33942263.nnue

# list the native binaries produced by all-arches
ls -l bin/

Getting help

Open an issue with the operating system, CPU model, archive name, the exact command or GUI action, and the raw engine output. For protocol issues, include the complete handshake and the line that failed. Do not paste only “it does not work”; the logs are what make a report reproducible.
