How to participate

What actually helps.

  • A reproducible report. Command, FEN, build and output — not a summary.
  • A test position. Legal, with a clear best move and a source.
  • A narrow patch. One behaviour, one reason, one test result.
  • A documentation correction. If the site disagrees with the binary, the site is wrong.
  • A benchmark run. Same protocol, different hardware — useful context, not a competition.
Expectations

Fafnir is maintained in spare time. There is no support SLA and no guaranteed response window. A clear report is more likely to get attention than a repeated bump.

Etiquette

Direct about code, considerate about people.

Disagreement is normal in engine development. A patch can be rejected without the author being rejected. Harassment, personal attacks and deliberate disruption are not welcome.

The repository includes CODE_OF_CONDUCT.md and SECURITY.md. Read both before a contentious thread or a vulnerability report.
