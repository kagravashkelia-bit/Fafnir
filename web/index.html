What is inside

Search, evaluation and protocol — without the fog.

Fafnir is deliberately narrow: one engine, one protocol, one embedded network, and a build system that tells you which instructions it used.

Inside the search

Every node has a reason to exist.

The search follows the Stockfish development playbook with an in-house implementation: a 3-entry transposition cluster, age-based replacement, LMR with shallow re-search, singular extensions with multicut, ProbCut, and null-move pruning with verification.

  • Main, low-ply, capture, continuation (2×2), pawn and correction history
  • MVV-LVA plus SEE ordering in a dedicated MovePicker
  • Soft and hard time limits with ponder support
  • Aggressivity 0–100 modulates evaluation optimism

Architecture

A small surface area, documented.

The engine is split into a UCI front end, a search controller, a move picker, an NNUE bridge and a thin set of core types. Vendored Stockfish code is isolated behind the probe.

  • No JNI bridge: the unbuildable Java integration was removed in 2.0.
  • WASM API kept behind __EMSCRIPTEN__ with five C functions.
  • Per-architecture object directories prevent flag mixing.
  • One documented patch to the vendored SFNNv17 snapshot.

FAQ

Short answers to fair questions.

Does Fafnir need an external NNUE file?

No. The network is embedded with incbin at compile time. You can move the binary alone and it still evaluates positions. The WASM build disables embedding with NNUE_EMBEDDING_OFF.

Which build should I download?

Start with the safe x86-64 archive if you are unsure. AVX2 is the right choice for most CPUs from 2013 onward; SSE4.2 covers older machines. The engine will not start on a CPU that lacks the instructions in the build you chose.

Is this Stockfish?

No. Fafnir is a separate engine with its own search implementation and UCI front end. It uses the Stockfish development NNUE architecture (SFNNv17) and vendored evaluation code, which is why the project is GPLv3. The search, move picker, controller and protocol layer are in this repository.

Can I use it in a tournament or on a website?

Yes, subject to the GPLv3 and the rules of the event or platform. The WASM public edition is still in preparation; the native UCI engine is the supported build today.

Why are there only five UCI options?

Because only five are implemented. Syzygy tablebases and opening books are not declared until they actually work. Unknown options return info string unknown UCI option.
