Testing

Fafnir's 100-position EPD regression suite: categories, strict best-move rule, commands, interpretation, control games and CI smoke tests.

Fafnir 2.0Updated 2 November 2026Reference

The regression suite is a 100-position EPD test set with a deliberately strict rule: a position is a hit only when the engine's UCI bestmove matches one of the EPD bm moves. There is no partial credit and no “near miss” category.

The suite

SourcePositionsFocus
Bratko-Kopec24Tactical calculation and positional tactics
Kaufman19Opening and strategic accuracy (strict bm positions)
Nolot11Sharp tactical positions
LCT-II14 positional + 12 combinationLong-term positional and tactical tests
Rybka Forum20Endgame and conversion tests

The runner converts EPD SAN best moves to UCI internally, so the test file stays readable. It requires Python 3.9+ and no third-party packages.

Running the suite

Commandsbash
python tests/tests.py bin/Fafnir.exe --depth 18
python tests/tests.py bin/Fafnir --movetime 1000
python tests/tests.py bin/Fafnir --depth 20 --hash 128 --threads 1
python tests/tests.py bin/Fafnir --depth 18 --category FINALES_RYBKA
FlagMeaning
--depth <n>Search each position to a fixed depth
--movetime <ms>Use a fixed time per position instead of depth
--hash <mb>Set Hash before the run
--threads <n>Set Threads before the run
--category <name>Restrict to one EPD category

Pick either depth or movetime. A depth run is more reproducible; a movetime run reflects tournament conditions but depends on machine load.

Interpreting the result

ResultMeaning
HITThe engine's bestmove is one of the EPD best moves
MISSThe engine chose a different legal move
ERRORThe engine failed to produce a valid bestmove
TimeoutNo bestmove before the runner's deadline
i
How to read the scoreA single run is not a rating. The suite is a regression gate: compare the same binary, depth and Hash across changes. A one-position difference can be noise; a pattern across a category is a signal.

Control games

tests/records/ contains PGN archives of control games, including draws against Stockfish and Reckless 0.9.0. These are historical records, not a claim of current strength. They are useful for replaying a position or checking how a configuration behaved in a real game.

CI smoke test

build-native.yml does not run the full EPD suite. It performs a UCI smoke test after building each native archive, which catches a binary that cannot start or answer the handshake. The EPD suite is run locally when changing search or evaluation behaviour.

isready
quit

Adding a position

  1. Add a TestCase entry in tests/tests.py with a name, category, FEN, best moves and source.
  2. Include all six FEN fields if possible; the runner can add neutral counters, but explicit is better.
  3. Verify the position is legal and that the best move is expressed in SAN.
  4. Run the suite before and after the change you are testing.

Limitations

  • Best-move matching ignores evaluation quality: a move that is objectively equal but not listed counts as a miss.
  • The suite is small compared with a full game-pair match; it detects regressions, not absolute strength.
  • Time-based runs vary with hardware and background load.
  • There is no built-in bench command; use the documented UCI sequence for speed measurements.
