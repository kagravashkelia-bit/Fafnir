Build from source

Build Fafnir on Windows, Linux or Emscripten: requirements, make targets, ISA flags, compiler overrides and verification.

Fafnir 2.0Updated 2 November 2026Reference

Fafnir builds with a C++17 toolchain and GNU Make. The root Makefile handles native Windows and Linux builds; Makefile.wasm handles Emscripten. CI validates g++ on Linux and Windows; other compilers are accepted through CXX= but are not covered by CI.

Requirements

ToolMinimumNotes
C++ compilerC++17g++ is CI-validated. Clang and MSVC are accepted via CXX=.
MakeGNU MakeMSYS2 provides it on Windows.
Shellcmd.exe, MSYS2 sh, bashThe Makefile is portable across them.
Emscriptenemcc in PATHOnly required for Makefile.wasm.
Python3.9+Only required for the EPD test runner.
✓
Safe defaultThe default target is make, which produces a binary safe on any x86-64 CPU (SSE2 only). It will not crash because of an unsupported instruction set, regardless of how the build machine is configured.

Quick start

Clone and buildbash
git clone https://github.com/kagravashkelia-bit/Fafnir.git
cd Fafnir
make -j8
./bin/Fafnir
Tuned and explicit buildsbash
make clean
make ARCH=native -j8
make ARCH=x86-64-avx2 -j8

Make targets

TargetResult
makeDefault ARCH (x86-64 safe), output bin/Fafnir or bin/Fafnir.exe
make ARCH=nativeTuned for the build machine (-march=native)
make all-archesBuilds every ISA in bin/Fafnir-<arch>
make cleanRemoves build/ and bin/
make rebuildClean followed by the default build
make runBuilds and starts the engine
make helpPrints the architecture matrix

all-arches builds x86-64, x86-64-ssse3, x86-64-sse4.2, x86-64-avx2 and x86-64-avx512. Each architecture compiles into its own build/<ARCH>/ directory, so flags are never mixed between binaries. The unsuffixed bin/Fafnir always reflects the last architecture built.

Architecture matrix

ARCHFlagsBaseline
x86-64-msse2Any x86-64
x86-64-ssse3-mssse3Core 2 / K10 and later
x86-64-sse4.2-msse4.2 -mpopcntNehalem / Bulldozer and later
x86-64-avx2-mavx2 -mbmi -mbmi2 -mpopcnt -mlzcntHaswell / Excavator and later
x86-64-avx512-mavx512f -mavx512bw -mavx512dq -mavx512vl -mavx512vnniSkylake-X / Ice Lake and later
native-march=nativeThis build machine only

Choosing a target above your CPU's capability produces a binary that crashes with an illegal instruction. If you distribute a build, use the lowest ISA that covers your audience, or publish separate archives like the official release.

Windows

The CI workflow uses MSYS2 with g++. From an MSYS2 shell in the repository root:

MSYS2 buildbash
pacman -S --needed base-devel mingw-w64-x86_64-gcc make
make ARCH=x86-64-avx2 -j8
.\bin\Fafnir.exe
i
Shell portabilityFrom cmd.exe, the Makefile uses the Windows mkdir and path conventions. It is idempotent: an existing directory no longer aborts the build. Do not mix cmd.exe and MSYS2 temporary files in the same build tree.

Linux

Debian / Ubuntubash
sudo apt install build-essential
make ARCH=x86-64-sse4.2 -j"$(nproc)"
./bin/Fafnir

The binary is produced directly; there is no install step. Copy it to a stable path and point your GUI at that path.

Using another compiler

Compiler overridebash
make CXX=clang++ ARCH=x86-64-avx2 -j8
make CXX=g++ ARCH=native -j8
i
CI coverage is narrower than the MakefileClang and MSVC are not validated by CI. They are accepted by the Makefile, but a successful build on your machine is not the same as the project's tested configuration. g++ 15.2.0 is the reference compiler for the published benchmarks.

WebAssembly

Emscripten buildbash
make -f Makefile.wasm

Requires emcc in PATH. Output goes to build-wasm/Fafnir.js and build-wasm/Fafnir.wasm. Network embedding is disabled with NNUE_EMBEDDING_OFF, so the WASM artifact does not carry the 94 MB network inside the binary. See WebAssembly for the C API and current status.

Verify the build

Smoke testbash
printf 'uci\nisready\nquit\n' | ./bin/Fafnir | grep -E 'id name|uciok|readyok'

Expected output includes id name Fafnir 2, uciok and readyok. The same sequence is used by the build-native.yml CI workflow.

Build troubleshooting

SymptomLikely causeFix
make: command not foundMake is not installed or not in PATHInstall build-essential / MSYS2 make
g++: not foundCompiler missingInstall g++ and reopen the shell
mkdir abortsOld build tree or shell mismatchRun make clean, then rebuild
Illegal instruction at runtimeISA mismatchRebuild for a lower ARCH
emcc not foundEmscripten not activatedSource emsdk_env or add emcc to PATH
Linker out of memoryToo many parallel jobsLower -j
