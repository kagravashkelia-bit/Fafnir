Product

A search stack you can audit.

No hidden options, no mystery network file, no build that crashes on an older CPU. Fafnir exposes the parts that matter and documents how they fit together.

Search

The parts that decide a move.

The search core follows the style of Stockfish development with an in-house implementation. The list below is the actual stack, not a feature checklist copied from another engine.

TT

Transposition table

Clusters of three entries, generation counters and age-based replacement. Configurable from 1 to 1024 MB and resizable at runtime.

H

History heuristics

Main history, low-ply history, capture history, continuation history (2×2), pawn history and four correction-history tables.

MP

MovePicker

TT move, good captures (MVV-LVA + SEE), history-ordered quiets, bad captures, bad quiets, evasions, ProbCut and qsearch.

↓

Pruning & reductions

Razoring, futility pruning, null-move pruning with verification, IIR, ProbCut, singular extensions with multicut, and LMR.

=

Draw detection

SEE with pinned pieces, cuckoo detection of imminent repetition, repetition draws and the fifty-move rule integrated into the search stack.

⏱

Time management

Soft and hard limits, ponder support, and control by movetime, depth, wtime/btime, increments and movestogo.

StageWhat is generatedOrdering signal
1. TT moveThe hash move for this positionTransposition table
2. Good capturesCaptures that pass SEEMVV-LVA, then SEE
3. QuietsAll remaining quiet movesHistory + continuation history
4. Bad capturesCaptures that lose material by SEEMVV-LVA
5. Bad quietsQuiets deferred by pruningHistory
6. EvasionsLegal responses to checkTT, captures, history
7. ProbCut / qsearchTactical subset at reduced depthSEE and capture gain

Maximum search stack depth is MAX_PLY = 246. The root supports MultiPV from 1 to 256 variations.

Evaluation

A neural network that travels with the binary.

Fafnir embeds the default SFNNv17 network at link time. There is no sidecar file to lose, no path to configure, and no LFS pointer pretending to be a network.

  • Single-output architecture without PSQT
  • Feature sets: half_ka_v2_hm, full_threats, pp_3wide
  • Quantized evaluation normalized to pawn units
  • 98,668,604-byte network with a published SHA-256

Protocol

Five options. All of them real.

The engine declares only what it implements. This is the complete option surface of Fafnir 2.0.

Honest failureAn unrecognised option is not silently accepted. Fafnir answers info string unknown UCI option, which makes configuration mistakes visible in the GUI log.

Syzygy tablebases and opening books are not declared. They will appear only together with a working implementation — not as placeholders.

Deliberate limits

What Fafnir does not pretend to do.

No Syzygy tablebases yet

The protocol does not declare a tablebase option. When support lands, it will be implemented and tested before it is announced.

No opening book

Book selection belongs to the GUI or tournament manager. Fafnir does not ship a book or a book option.

No WASM public build yet

CI produces a Fafnir-WASM-Build artifact, but the public web edition is still in preparation. The API is documented so it can be reviewed and tested early.

No telemetry, no update check

The engine is a local process. It does not open network connections, phone home, or check for updates.

Read the protocol, then break it.

A reference is only useful if it matches the binary. Every command and option here is implemented in the current source.
