UCI reference

The complete Fafnir UCI contract: handshake, position, go limits, five options, info fields, MultiPV and error behaviour.

Fafnir 2.0Updated 2 November 2026Reference

Fafnir implements the Universal Chess Interface. Commands are read line by line from standard input; replies are written to standard output. The engine does not use standard error for protocol output.

Identity and handshake

uci prints the engine identity and the complete option list, then uciok. This is the only supported discovery mechanism. The current identity is:

Identity stringstext
id name Fafnir 2
id author Anthony
CommandBehaviour
uciPrints id, every option and uciok
isreadyPrints readyok when the engine can accept commands
ucinewgameResets the search state for a new game
positionSets the board from startpos or fen, optionally followed by moves
goStarts a search with the supplied limits
stopStops the current search as soon as possible
setoptionChanges a declared option
quitTerminates the engine

Position setup

Two forms are supported. The move list is applied after the base position, in UCI coordinate notation.

positiontext
position startpos
position startpos moves e2e4 e7e5 g1f3
position fen rnbqkbnr/pppppppp/8/8/8/8/PPPPPPPP/RNBQKBNR w KQkq - 0 1
position fen 8/8/8/8/8/8/8/K6k w - - 0 1 moves a1a2
i
FEN completenessThe engine expects a complete, legal FEN. EPD test positions often omit the halfmove and fullmove counters; the Python test runner adds neutral counters before sending them. If you build a FEN by hand, include all six fields.

Search limits

go accepts the following parameters. They can be combined; the engine stops at the first limit that is reached.

ParameterMeaning
depth <n>Stop after completing iteration n
movetime <ms>Search for approximately ms milliseconds
wtime <ms>White's remaining clock
btime <ms>Black's remaining clock
winc <ms>White's increment
binc <ms>Black's increment
movestogo <n>Moves remaining before the next time control
ponderStart in ponder mode
infiniteSearch until stop
go examplestext
go depth 18
go movetime 3000
go wtime 300000 btime 300000 winc 2000 binc 2000
go wtime 60000 btime 60000 movestogo 20
go infinite

Options

The engine declares exactly five options. The ranges and defaults below are the values printed by uci, not approximations.

OptionTypeDefaultMinMaxImplementation
Hashspin1611024Resizable transposition table, applied immediately
Threadsspin11128Lazy SMP helper threads
MultiPVspin11256Root search by variation
Move Overheadspin5005000Margin subtracted from the clock
Aggressivityspin00100Evaluation optimism during search
setoptiontext
setoption name Hash value 128
setoption name Threads value 4
setoption name MultiPV value 3
setoption name Move Overhead value 100
setoption name Aggressivity value 25
i
Unknown options are rejectedAn unrecognised option is not silently ignored. Fafnir answers info string unknown UCI option, so a typo is visible in the GUI log. Only the five options above are valid in 2.0.

Output during search

While searching, the engine emits info lines. The fields below are the ones Fafnir produces; a GUI must not assume that optional fields such as hashfull or tbhits are present.

FieldMeaning
depthCompleted search depth
seldepthMaximum selective depth reached
score cp <n>Score in centipawns from the side to move
score mate <n>Mate distance in moves
nodesNodes searched in this iteration
npsNodes per second
timeElapsed search time in milliseconds
pvPrincipal variation in UCI coordinate notation
info and bestmovetext
info depth 20 seldepth 34 score cp 35 nodes 553530 nps 464370 time 1192 pv e2e4 e7e5 g1f3 b8c6
bestmove e2e4 ponder e7e5

bestmove is always the final line of a search. The ponder field is a hint for the GUI; it is not part of the move that must be played.

MultiPV output

With MultiPV greater than one, the engine reports one info line per root variation. The multipv field identifies the rank. The final bestmove still corresponds to the first variation.

MultiPVtext
setoption name MultiPV value 3
go depth 12
info depth 12 seldepth 18 multipv 1 score cp 34 ... pv e2e4 ...
info depth 12 seldepth 18 multipv 2 score cp 28 ... pv d2d4 ...
info depth 12 seldepth 18 multipv 3 score cp 21 ... pv g1f3 ...
bestmove e2e4 ponder e7e5

Error behaviour

InputResponse
Unknown optioninfo string unknown UCI option
Unknown commandNo protocol reply; the command is ignored
Unknown go parameterIgnored; the search uses the recognised limits
Empty positionThe previous position remains in effect
stop with no searchNo reply
i
Protocol honestyFafnir does not invent a bestmove 0000 response for a normal search. 0000 is used by the WASM API when no move can be produced.

Complete session

Session flowtext
uci
isready
ucinewgame
setoption name Hash value 64
position startpos moves e2e4 c7c5
go movetime 1000
# ... info lines ...
bestmove g1f3 ponder d7d6
quit

GUI integration notes

  • Wait for uciok before sending isready.
  • Send ucinewgame between games if the GUI supports it; it clears stale search state.
  • Set Move Overhead to a value that covers your GUI's latency. The default is 50 ms.
  • Do not assume a tablebase or book option exists; it does not in 2.0.
  • Log the raw engine output when reporting a protocol bug. The exact info sequence matters.
