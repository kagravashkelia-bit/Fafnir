Architecture

Fafnir repository map, layer responsibilities, search data flow, Lazy SMP threading, vendored code boundaries and build graph.

Fafnir 2.0Updated 2 November 2026Reference

The repository is intentionally small at the top level. Most of the code is either the in-house engine or a vendored dependency with a documented boundary. This page maps the responsibilities.

Layers

LayerFilesResponsibility
Protocolsrc/ui/uci.cpp, uci.hppParse UCI, own the board, translate options and search limits
Entry pointsrc/ui/main.cppConstruct the UCI engine and run the console loop
Searchsrc/engine/search.hppIterative deepening, pruning, reductions, history, PV
Orderingsrc/engine/movepicker.cppStaged move generation and ordering
Controlsrc/engine/SearchController.cppThreads, time limits, lifecycle, stop
Evaluationsrc/engine/eval/Evaluation entry point and piece-square tables
NNUE bridgesrc/bridges/nnue_probe.cppInitialize and call the vendored SFNNv17 network
WASM APIsrc/ui/wasm_api.cppFive C functions exposed to JavaScript
Core typessrc/core/types.hppShared enums and small types

Data flow

  1. main.cpp starts UciEngine::main_loop().
  2. uci.cpp parses a command and updates the board or options.
  3. A go command calls SearchController, which launches the requested threads.
  4. search.hpp walks the tree, using MovePicker and the NNUE probe.
  5. Info lines and the final bestmove are written back to standard output.
  6. stop or a time limit asks the controller to finish the current iteration.

Threading model

Threads controls Lazy SMP helper threads. The main thread owns the search stack and the reported principal variation; helpers search the same root with different move ordering and share the transposition table. The controller owns the stop flag and the time checks, so a GUI stop does not need to interrupt a helper directly.

i
Concurrency boundaryThe shared transposition table is the only large cross-thread structure. Hash resizing must happen between searches, which is why the UCI layer applies setoption name Hash while the engine is idle.

The only local patch to the vendored snapshot changes EvalFileDefaultName in evaluate.h to point at assets/nnue/nn-252f33942263.nnue. When the snapshot is renewed, that patch must be reapplied.

Build graph

Each architecture compiles into build/<ARCH>/. The final link combines the UI, engine, probe and the required vendored Stockfish sources. There is no runtime plugin loading: the network and all engine code are in the binary.

Build layoutbash
make ARCH=x86-64-avx2 -j8
# build/x86-64-avx2/src/...      object files
# build/x86-64-avx2/third_party/ vendored objects
# bin/Fafnir                     final binary

Design decisions

  • Safe default. make uses SSE2 so a distributable binary does not crash on older CPUs.
  • No runtime network path. Embedding removes a class of deployment errors.
  • No fake options. The protocol surface is exactly the implemented surface.
  • Remove unbuildable code. The JNI bridge was deleted rather than shipped broken.
  • One source of truth for the site. The website is generated from the same repository that ships the engine.

Where to start reading

For the protocol, read src/ui/uci.cpp. For move choice, read src/engine/search.hpp alongside movepicker.cpp. For evaluation, read src/bridges/nnue_probe.cpp, then the vendored nnue/ directory. The build files are short enough to read end to end.
