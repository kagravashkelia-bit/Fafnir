Contact

The repository is the contact surface.

There is no published support email and no chat server. GitHub issues keep the report, the discussion and the fix in one public thread, which is better for a project of this size.

◎

Bug report

Open an issue with the OS, CPU model, archive or commit, the exact command or GUI action, and the raw engine output. For an illegal instruction, state which ISA build you used.

Open an issue
＋

Feature proposal

Describe the behaviour, the expected result, and why it belongs in the engine rather than the GUI. Proposals are discussed before implementation.

Propose a change
!

Security

Do not open a public issue for a vulnerability that could affect users. Follow the process in SECURITY.md in the repository.

Security policy
§

License question

Open an issue if a notice is unclear or appears incomplete. This is not legal advice; consult a lawyer for a legal decision.

License overview
What to include

  1. Environment

    OS version, CPU model and build archive or commit.

  2. Reproduction

    The shortest command, FEN or GUI action that shows the problem.

  3. Output

    The raw engine log, not a paraphrase. Include the full UCI handshake for protocol issues.

  4. Expectation

    What you expected and what happened instead.

!
No SLAFafnir is maintained in spare time. A clear report is more likely to get attention; repeated bumps are not a priority signal.
